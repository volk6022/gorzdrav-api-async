## Что делает проект

Асинхронный REST-сервер оборачивает внутреннее API медицинской системы записи Горздрав СПб и даёт разработчикам программный доступ к данным о поликлиниках, врачах и свободных талонах — без ручного мониторинга сайта.

Сервер принимает запросы по HTTP, управляет пулом соединений к upstream-API, кэширует справочные данные на 1 час и возвращает структурированный JSON с валидацией через Pydantic.

---

## Проблема и решение

### Проблема

Gorzdrav.spb.ru не предоставляет публичного API. Разработчики систем мониторинга свободных слотов, Telegram-ботов уведомлений или автоматических помощников записи вынуждены либо вручную обходить сайт, либо писать хрупкие синхронные скрипты. При высоком спросе на конкретного специалиста талоны исчезают за секунды — отследить это вручную практически невозможно. Синхронные решения плохо масштабируются: один медленный ответ от upstream блокирует весь процесс.

### Решение

Проект предоставляет готовый FastAPI-сервер с асинхронным клиентом к внутреннему API Горздрава. Пул из 5 соединений (очередь до 1 000 запросов) обрабатывает параллельные обращения без блокировок. Retry-логика с экспоненциальной задержкой (до 3 попыток) перехватывает сетевые сбои. Кэш на 1 час снижает нагрузку на upstream для справочных данных (районы, ЛПУ, специальности). Иерархия кастомных исключений (NoDoctors, NoTickets, Api603Timeout и др.) позволяет точечно обрабатывать бизнес-ошибки upstream.

### Результат

- Производительность: [NEEDS VERIFICATION] — бенчмарки не задокументированы
- Надёжность: retry до 3 попыток с экспоненциальным backoff на каждый запрос
- Снижение нагрузки: кэш TTL 3 600 с для справочных эндпоинтов
- Масштаб очереди: пул поддерживает до 1 000 параллельных запросов в очереди

## Формулировки для резюме

### Bullet points

- Разработал асинхронный Python-клиент к закрытому API Горздрав СПб на httpx + Pydantic v2, реализовав retry-логику с экспоненциальным backoff и иерархию из 6 кастомных исключений
- Реализовал FastAPI-сервер с пулом из 5 асинхронных соединений и очередью до 1 000 запросов, исключив блокировки при параллельных обращениях
- Спроектировал in-memory кэш (aiocache, TTL 1 час) для справочных эндпоинтов, снизив количество upstream-запросов для повторяемых данных
- Реализовал URL-парсер ссылок Горздрава с поддержкой двух форматов (regex и JSON-декодирование), позволяющий интегрировать сервис с любым Telegram-ботом или скриптом мониторинга

### Описание для секции «Проекты»

**gorzdrav-api-async** — асинхронный REST-прокси для внутреннего API медицинской системы записи Горздрав СПб, дающий программный доступ к данным о врачах, расписании и свободных талонах. Стек: Python 3.10+, FastAPI, httpx, Pydantic v2, aiocache. Ключевые решения: пул соединений, retry с backoff, кэширование справочников и типобезопасные Pydantic-модели для всех ответов upstream.

### Кейс для портфолио

ПРОБЛЕМА: Разработчики Telegram-ботов и систем мониторинга записи к врачам в СПб не имеют публичного API — они вынуждены вручную парсить сайт синхронными скриптами, которые ломаются при малейшем изменении вёрстки и не справляются с параллельной нагрузкой.

РЕШЕНИЕ: Разработан асинхронный FastAPI-сервер, оборачивающий внутреннее API Горздрав СПб: 7 REST-эндпоинтов (районы, ЛПУ, специальности, врачи, расписание, талоны, парсинг/генерация ссылок), пул соединений на 5 клиентов, кэш справочников на 1 час, retry-логика на 3 попытки.

РЕЗУЛЬТАТ: Любой разработчик может поднять сервер одной командой и строить поверх него мониторинги, уведомления и интеграции, не разбираясь в деталях upstream-протокола; retry и кэш обеспечивают устойчивость к нестабильному upstream.

### Soft skills / подходы, видные из кода

- **Async-first мышление**: весь стек построен вокруг `asyncio` — нет синхронных блокировок
- **Defensive programming**: кастомная иерархия исключений с кодами ошибок upstream
- **Separation of concerns**: клиент, модели, конфиг, валидация и сервер — в отдельных модулях

## Ограничения и зоны роста

- **Нет тестов** — ни unit, ни интеграционных; добавление pytest + respx закрыло бы этот пробел
- **Нет логирования** — отсутствует структурированный лог для debug и мониторинга (loguru / structlog)
- **Нет Dockerfile** — деплой описан только текстом, нет контейнеризации из коробки
- **Жёсткая привязка к Горздрав СПб** — URL и структура upstream зашиты; при смене API сломается
- **Нет rate limiting** — отсутствует защита от злоупотреблений на входящем уровне
- **Нет аутентификации** — сервер полностью открытый, не предназначен для публичного деплоя без обёртки
- **Конфиг не через env-переменные** — параметры прописаны в `config.py`, а не в `.env` / переменных среды
